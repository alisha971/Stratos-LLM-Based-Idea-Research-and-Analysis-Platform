# W9 — Export Worker: Upgrade Plan

## 1. What it does today (plain language)

The last worker (`app/workers/export_worker.py`) turns the assembled report into a PDF using ReportLab: title, section headings, paragraph text with citation markers, saved to `exports/{report_id}.pdf`, records an `ExportRecord`, emits `export_done`. Functional but visually bare — black text on white, no cover, no charts, no branding. **The PDF is the only artifact the customer keeps and forwards** — its polish is disproportionately what people judge (and screenshot).

## 2. Who it competes with (the quality bar)

Document-generation engines (DocRaptor, PDFMonkey, Carbone) and, more importantly, **the look of reports customers already respect**: CB Insights / a16z market maps, McKinsey-style layouts. The bar: cover page, table of contents, headers/footers with page numbers, at least 1–2 charts, consistent typography, clickable links. Also: people paste reports into their own docs — so Markdown/DOCX exports matter almost as much as PDF.

## 3. Feature plan (do in order)

### X1 — Template system on ReportLab Platypus

- Refactor `_render_pdf` into `app/services/pdf_renderer.py` with a `ReportTemplate` class: brand color pair (env-configurable, default a deep navy + accent), font pair (Helvetica family is built-in and safe; embed an OFL font like Inter via TTF if you want more character), spacing constants, and reusable flowables (SectionHeading, BodyPara, PullQuote, StatCallout).
- Page furniture via `onPage` callbacks: footer "Generated by Stratos — stratos.yourdomain.com" + page number; thin accent rule under the header. (This footer is also the free-tier watermark from doc 08 — make it removable by plan flag.)

### X2 — Cover page + table of contents

- Cover: report title ("Market Research Report: {idea}"), date, a subtle full-width accent band, "Prepared by Stratos AI" and the report's quality stats (sources analyzed, sections, audit score from W8-A6 — numbers on covers look authoritative because they are).
- TOC: ReportLab's `TableOfContents` flowable with `afterFlowable` notify hooks on section headings — standard Platypus pattern, ~30 lines. Two-pass build (`multiBuild`) required — use it.

### X3 — Charts (the wow feature)

- Add `matplotlib` (Agg backend, no display needed). Render to PNG in-memory (`BytesIO`) → ReportLab `Image` flowable. Two charts for v1:
  1. **Trend momentum line** — the pytrends interest-over-time series (W4-T2) as a clean single-line chart with the momentum label annotated.
  2. **Competitor landscape scatter/quadrant** — from W5-K4's positioning axes: competitors as labeled dots on the two axes; the user's idea as a highlighted star. (If competitor data is absent, skip silently.)
- Style both with the template's brand colors, no chart junk (no gridlines beyond faint y, no titles duplicated by captions). Deterministic rendering: fixed figsize/dpi (150), fixed seed for any jitter.

### X4 — Clickable citations + references

- Inline `[$n]` markers become internal links to the References page (`linkURL`/anchor pattern); each reference's URL is an external clickable link. ReportLab supports both via `<a href>` in Paragraph markup — sanitize the URL first (escape `&`, reject non-http(s)).

### X5 — Markdown + DOCX exports

- Markdown: trivial — the assembler (W8-A1) already stores markdown; expose `GET /exports/{report_id}/file?format=md` returning it with `Content-Disposition`.
- DOCX: `python-docx` — map headings/paragraphs/references (skip charts in v1 or embed the same PNGs). Same endpoint with `?format=docx`. Store all rendered formats in R2 under `exports/{report_id}.{ext}`.
- Update `../05-INTEGRATION-CONTRACT.md`: the `format` query param (`pdf` default) and the frontend download button becomes a small menu (PDF / Word / Markdown).

### X6 — Deterministic performance + safety rails

- Cap: render time budget 60 s (Celery soft limit already exists); if charts fail, render without them (fail-soft, log); PDF size target < 3 MB (downscale chart DPI if exceeded).
- Text sanitization: escape XML entities in all user/LLM text before Paragraph markup (ReportLab paragraphs parse mini-HTML — an unescaped `<` from scraped content will crash the build; this is also an injection surface, see security doc §6).

### X7 — Standalone product mode (optional)

`POST /v1/render` with `{document: markdown+metadata, template}` → PDF/DOCX. A markdown-to-branded-PDF API is a real (if crowded) product; only pursue if the API business line takes off.

## 4. Testing checklist (run all before production)

1. **Golden-file test:** fixture report → render → assert: page count in expected range, PDF magic bytes, text extraction (`pypdf`) contains every section title, the footer string, and "References". Keep the fixture PDF in the repo for eyeball diffs.
2. **Sanitization (release blocker):** section text containing `<b>bold</b> & <script>alert(1)</script> and a raw < angle` → render must succeed and output the literal text. Also a citation URL of `javascript:alert(1)` → link stripped.
3. **Chart fail-soft:** matplotlib mocked to raise → PDF still renders, no chart, warning logged, `export_done` fires.
4. **TOC/link test:** extract annotations with pypdf → every inline citation link resolves to the references page; every reference URL annotation matches the citation URL.
5. **Format matrix:** `?format=pdf|md|docx` each download, open, and contain the executive summary text (docx checked via python-docx read-back).
6. **Plan watermark test:** free-plan report → footer watermark present; pro-plan → absent.
7. **Size/time:** fixture 8-section report renders ≤ 20 s, ≤ 3 MB (assert both in the test).
8. **Visual review (manual):** print one real report to paper (seriously — layout bugs hide on screens). A non-developer looks at it for 2 minutes: would they attach this to an email to an investor? Fix whatever makes them hesitate.
9. **Regression:** pipeline smoke passes; R2 upload path (main plan B6) stores all formats.
