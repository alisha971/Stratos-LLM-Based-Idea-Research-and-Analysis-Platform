## 1️⃣ What the Research Worker IS responsible for

**Single sentence definition:**

> The Research Worker collects high-signal external evidence (URLs + cleaned text) relevant to the clarified idea and persists it for downstream section writers.
> 

### Responsibilities

✔ Query external search APIs

✔ Fetch & lightly scrape web pages

✔ Clean and normalize text

✔ Store **raw evidence** (Astra)

✔ Store **structured metadata** (Postgres)

✔ Emit progress + completion events

## 8️⃣ Worker Stub (what you implement first)

### `workers/research_worker.py`

```python
@celery_app.task(
    bind=True,
    autoretry_for=(Exception,),
    retry_backoff=10,
    retry_kwargs={"max_retries": 3},
)
def run_research(self, report_id: str):
    db = SessionLocal()

    try:
        report = db.query(models.Report).get(report_id)
        session = db.query(models.Session).get(report.session_id)

        publish_event("searching_sources", {"report_id": report_id})

        service = ResearchService(db=db)

        queries = service.generate_queries(session.clarified_summary)

        for query in queries:
            results = service.search(query)

            for r in results:
                page = service.scrape(r.url)
                clean_text = service.clean(page.html)

                service.persist(
                    report_id=report_id,
                    source=r,
                    evidence=clean_text
                )

        publish_event("research_done", {"report_id": report_id})

    except Exception as e:
        publish_event("research_failed", {
            "report_id": report_id,
            "error": str(e)
        })
        raise
    finally:
        db.close()

```

## 1️⃣1️⃣ Edge Cases (You MUST handle)

| Case | Behavior |
| --- | --- |

| Timeout | Retry |

## 1️⃣3️⃣ Failure Paths

### Failure 1 — SERP API down

- Retry 3 times
- Emit `research_failed`
- Orchestrator may retry later

### Failure 2 — All pages blocked

- Store snippets only
- Still emit `research_done`
- Downstream continues with limited evidence

## 1️⃣4️⃣ Why this structure was chosen

### Worker vs Service split

- **Worker** = orchestration + retries
- **Service** = testable business logic

This keeps:

- Celery thin
- Logic reusable
- Tests sane

### DB split (Postgres vs Astra)

- Postgres → relationships
- Astra → volume + vectors

Exactly correct for scale.
