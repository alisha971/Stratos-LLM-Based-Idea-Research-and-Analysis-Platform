# 1️⃣ Endpoints

The Outline Engine is **not user-facing**.

It exposes **internal orchestration endpoints only**.

---

## 1. `POST /internal/outline/start`

### Purpose

Trigger outline generation for a report **after clarification consent**.

---

### Method

```
POST

```

---

### Request Schema

```json
{
  "report_id": "string (uuid)"
}

```

### Validation Rules

- `report_id` must exist
- Report must belong to a session with:
    - `sessions.clarified_summary IS NOT NULL`
- Outline must not already be finalized (or must be explicitly replaceable)

---

### Example Request

```json
{
  "report_id": "7f3a0a3e-9c5c-4e21-9a4f-2c45db29d3c1"
}

```

---

### Response Schema (Immediate ACK)

```json
{
  "status": "accepted",
  "report_id": "7f3a0a3e-9c5c-4e21-9a4f-2c45db29d3c1",
  "message": "Outline generation started"
}

```

> ⚠️ Important:
> 
> 
> This endpoint does **not** return section titles.
> 
> Results arrive via SSE (`outline_ready`).
> 

---

### HTTP Status Codes

| Code | Meaning |
| --- | --- |
| 202 | Job accepted |
| 400 | Invalid or missing report_id |
| 404 | Report not found |
| 409 | Outline already exists |
| 500 | Unexpected failure |

# 4️⃣ Outline Generation Rules (Authoritative)

### A. Non-Negotiable Sections (Always Included)

These **must** be present, in order:

1. Problem Context & Validation
2. Target Users & Personas
3. Existing Solutions
4. Competitor Landscape
5. Market & Industry Trends
6. Opportunities & Gaps
7. Risks & Open Questions

---

### B. Optional Derived Sections

Derived **only** from language in `clarified_summary`.

Rules:

- Max **3** optional sections
- Appended **after** core sections
- Deterministic titles only (no creative phrasing)

Examples:

| Detected Signal | Section Added |
| --- | --- |
| compliance / regulation | Regulatory Considerations |
| API / ML / infra | Technical Feasibility |
| monetization unclear | Pricing & Monetization |
| marketplace | Supply–Demand Dynamics |

---

# 5️⃣ Persistence Contract (DB Writes)

### Table: `sections`

For each generated section:

```sql
INSERT INTO sections (
  id,
  report_id,
  title,
  order_index
)

```

Rules:

- `order_index` starts at 1
- Titles must be unique per report
- Operation should be **idempotent**
    - Either:
        - fail if sections exist
        - or delete & recreate (explicit design choice)

---

### Example Inserted Rows

| order_index | title |
| --- | --- |
| 1 | Problem Context & Validation |
| 2 | Target Users & Personas |
| 3 | Existing Solutions |
| 4 | Competitor Landscape |
| 5 | Market & Industry Trends |
| 6 | Opportunities & Gaps |

| 8 | Technical Feasibility |

## 4️⃣ Failure Paths (2)

---

### ❌ Failure Path 1 — Missing Clarified Summary

**Cause:**

- Orchestrator triggers outline before clarification completed

**Detection:**

```python
if not session.clarified_summary:
    raise ValueError("Clarified summary missing")

```

**Behavior:**

- Worker fails
- No sections created
- Emit failure event

```json
{
  "type": "outline_failed",
  "payload": {
    "report_id": "uuid",
    "error": "Clarified summary missing"
  }
}

```

**Outcome:**

- Orchestrator halts pipeline
- UI shows error state

---

### ❌ Failure Path 2 — LLM Returns Invalid Output

**Cause:**

- LLM returns prose or malformed JSON

**Handling:**

- Retry up to 3 times
- On final failure:
    - Log raw output
    - Emit failure event

**Outcome:**

- No partial DB writes
- System remains consistent
